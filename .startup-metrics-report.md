## Key recon findings

- `web/frontend/vendor/moq-playa/packages/player/src/stats.ts` already computes a
  `TTFFBreakdown` (`transportConnectedMs`, `setupCompleteMs`, `catalogReceivedMs`,
  `firstObjectReceivedMs`, `decoderConfiguredMs`, `firstFrameRenderedMs`).
  `MoqPlayer.tsx` reads only `stats.timeToFirstFrameMs` and drops the breakdown.
  MoQ player-side phases are therefore nearly free.
- `PerformanceResourceTiming` is used nowhere in the frontend today.
- `WhepPlayer.tsx` already calls `getStats()` twice per tick (`whepViewerLatencyMs`
  reads `candidate-pair.currentRoundTripTime`; inline poll reads `inbound-rtp`).
- `CSV_COLUMNS` in `src/metrics.py` is a hand-maintained flat list; the latency
  columns are duplicated there rather than spliced from `latency_budget`.
- Publisher `publish_success` detection already exists per protocol in
  `src/upload_service.py` (RTMP/WHIP ~967-971, SRT ~2140-2141, MoQ ~2656-2666).
